# Niko Drone Simulator - 操控系統規範說明書 (Control System Spec)

本文件定義了環境力學、物理引擎與視覺表現之間的對位關係，確保系統具備高度的物理完整性。

## 1. 環境力學同步 (Environment & Atmosphere)

### 1.1 時間源一致性
*   **規則**：`WindManager` 的亂流演算必須使用渲染器的 `rendererTime` (全域環境時鐘) 驅動。
*   **目的**：確保視覺（雲層流動）與物理（風力受力）在渲染幀層級完美對位，消除因雙時鐘源導致的同步誤差。

### 1.2 數據主權與單一寫回 (Data Sovereignty)
*   **原則**：邏輯組件（如 `WindManager`）必須為無狀態的純計算組件（Stateless Pure Functions）。
*   **限制**：嚴禁邏輯組件直接引用或修改 `DroneState` 單例。
*   **寫回點**：環境狀態（如 `currentWindAngle`）的更新權力僅限於協調層（`Renderer` 或 `Main Loop`），確保狀態變更可追蹤。

### 1.3 風向與視覺極性對位 [v1.7.9.10 憲法級定義]
為解決風向頻繁被 Agent 改壞的問題，定義以下絕對準則：
*   **風向定義 (Source)**：$0^\circ$ 為北風 (來自北方)，$90^\circ$ 為東風。
*   **流向定義 (Flow)**：風流動的方向。$Flow = Source + 180^\circ$。
*   **物理受力**：飛機受力方向必須與 **流向 (Flow)** 一致。
    *   *例*：北風 ($0^\circ$) -> 流向南 ($180^\circ$) -> 飛機往 $-Z$ 軸移動。
*   **視覺指標**：
    *   **HUD 箭頭**：必須指向 **流向 (Flow)**，即箭頭尖端指向風吹去的方向。
    *   **場地風旗**：必須指向 **流向 (Flow)**。
    *   **雲層位移**：雲層在螢幕上的移動方向必須與 **流向 (Flow)** 呈 **180° 反向** (相對於相機)。
        *   *原理*：風向右吹 (流向右)，雲層紋理應向右位移。若使用 $U$ 座標，$visualWindVX$ 為正，則 $U$ 應減少以使紋理向右移動。

## 2. 物理引擎基準 (Physics Baseline)

### 2.1 座標系與極性 [v1.7.9.9 憲法級標註]
*   **注意**：本規範定義了物理運動與視覺姿態的絕對對位，嚴禁隨意反轉！
*   **Yaw (航向)**：正值 ($+1.0$) 對應 **順時針旋轉 (CW)**。
*   **Roll (橫滾)**：正值 ($+1.0$) 對應向右推桿。
    *   **物理**：產生 **$-X$ 軸加速度** (對位 OpenGL 視角向右)。
    *   **視覺**：觸發 **順時針右傾** (`rotateM` 使用正值)。
*   **Pitch (俯仰)**：正值 ($+1.0$) 對應向前推桿。
    *   **物理**：產生 **$+Z$ 軸加速度** (向前)。
    *   **視覺**：觸發 **低頭前傾**。
*   **Throttle (油門)**：正值 ($+1.0$) 產生 **$+Y$ 軸升力**。

### 2.2 位移旋轉矩陣 (Rotation Matrix)
為確保視覺與物理的一致性，修正後的位移矩陣如下：
*   $X' = (-Roll) \times \cos(Yaw) + Pitch \times \sin(Yaw)$
*   $Z' = Roll \times \sin(Yaw) + Pitch \times \cos(Yaw)$

### 2.3 視覺姿態對位 (Visual Alignment)
渲染引擎必須執行以下符號以達成「推哪邊、飛哪邊、歪哪邊」：
*   **俯仰**：`rotateM(..., visPitch, 1, 0, 0)` (正值 = 低頭)。
*   **橫滾**：`rotateM(..., visRoll, 0, 0, 1)` (正值繞 Z = 順時針右傾)。
